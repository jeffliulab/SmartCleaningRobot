## 1. 任务描述

### 1.1 目标

模拟扫地机器人的核心场景：在一个房间内尽可能多地覆盖地面面积，同时**避开地面上的小物体**（如硬币、发卡、数据线），防止缠绕轮子。

### 1.2 与 T2 Coverage 的区别

| 维度 | T2 Coverage | T6 CoverageAvoid |
|------|-------------|-------------------|
| 物体 | 无 | 10 个随机物体 |
| 避障 | 仅避墙 | 避墙 + 避物体 |
| 传感器 | LiDAR + 覆盖率网格 | LiDAR + OracleDetector + 覆盖率 |
| 观测维度 | 1102 (含局部地图) | 81 (更精简) |

### 1.3 实际意义

这是模拟真实扫地机器人最接近的任务——在有障碍物的环境中高效清扫，是 T7 端到端任务的底盘导航部分。

## 2. 背景知识

### 2.1 覆盖率追踪（Coverage Tracker）

房间地面被划分为网格，机器人经过的格子标记为"已覆盖"：

```
┌──┬──┬──┬──┬──┬──┬──┬──┐
│  │  │  │░░│░░│  │  │  │
├──┼──┼──┼──┼──┼──┼──┼──┤
│  │  │░░│░░│░░│░░│  │  │
├──┼──┼──┼──┼──┼──┼──┼──┤
│  │░░│░░│██│░░│░░│  │  │  ██ = 机器人当前位置
├──┼──┼──┼──┼──┼──┼──┼──┤  ░░ = 已覆盖
│  │  │░░│░░│░░│  │  │  │     = 未覆盖
├──┼──┼──┼──┼──┼──┼──┼──┤
│  │  │  │░░│  │  │  │  │
└──┴──┴──┴──┴──┴──┴──┴──┘

覆盖率 = 已覆盖格子数 / 总可达格子数
```

| 参数 | 值 |
|------|-----|
| 网格分辨率 | 0.05m（每格 5cm×5cm） |
| 机器人覆盖半径 | 0.06m（经过时覆盖周围 6cm 范围） |

### 2.2 OracleDetector（训练用感知）

OracleDetector 直接从仿真器读取物体坐标（不使用相机），零计算开销：

```
OracleDetector 输出 = 3 个最近物体 × [r_norm, sin_theta]

r_norm = 物体距离 / FOV 范围 (2.0m)，归一化到 [0, 1]
sin_theta = sin(物体在机体坐标系中的角度)，范围 [-1, 1]

如果不足 3 个物体在 FOV 内，用 (1.0, 0.0) 填充（"很远，正前方"）
```

> 部署时将替换为 YOLOv8-nano 视觉检测器。

## 3. 环境详解

### 3.1 观测空间（81 维）

| 组件 | 维度 | 范围 | 说明 |
|------|------|------|------|
| velocity | 2 | 连续 | 前进线速度 + Z轴角速度 |
| lidar | 72 | [0,1] | 360→72 射线，/3.5m 归一化 |
| detector | 6 | [-1,1] | 3 最近物体 × [r_norm, sin_theta] |
| coverage | 1 | [0,1] | 当前覆盖率比例 |

### 3.2 动作空间（2 维）

| 索引 | 含义 | 范围 | 物理量 |
|------|------|------|--------|
| 0 | 线速度 | [-1,1] | ×0.3 → m/s |
| 1 | 角速度 | [-1,1] | ×2.0 → rad/s |

### 3.3 物体配置（10 个）

| 类型 | 数量 |
|------|------|
| 硬币 (Coin) | 3 |
| 发卡 (Hairpin) | 2 |
| 数据线 (Cable) | 2 |
| 橡皮 (Eraser) | 3 |

物体随机放置，最小间距 0.20m。

### 3.4 Episode 流程

```
1. [重置] 机器人随机位置/朝向，10 个物体随机放置
2. [循环] 每步:
   a. 读取观测 (速度 + LiDAR + 物体检测 + 覆盖率)
   b. 策略输出动作 (线速度 + 角速度)
   c. 仿真执行 2 步
   d. 更新覆盖率网格
   e. 计算奖励
   f. 终止条件:
      - 覆盖率 > 80% → 提前成功结束
      - 超时 120 秒 → 截断
3. [结束] 记录数据，重置
```

## 4. 奖励函数详解

| 组件 | 权重 | 触发条件 | 设计意图 |
|------|------|---------|---------|
| coverage | +2.0 | 每步新覆盖的格子数 | 核心目标：最大化覆盖率 |
| wall_collision | -3.0 | LiDAR 最小距离 < 0.20m | 惩罚撞墙 |
| obj_collision | -2.0 | 任何物体在 0.08m 内 | 惩罚碰到地面物体 |
| forward_bonus | +0.3 | forward_vel.clamp(min=0) | 鼓励前进（不原地打转） |
| time_penalty | -0.02 | 每步固定 | 鼓励高效清扫 |

**关键设计：** 碰撞物体的惩罚（-2.0）小于撞墙（-3.0），因为物体碰撞在实际中更常见，不应惩罚过重导致机器人过度谨慎。

## 7. 结果分析

### 7.1 预期训练时间线

| 阶段 | 步数 | 行为 |
|------|------|------|
| 0 - 200K | 随机移动，频繁碰墙碰物体 |
| 200K - 1M | 学会前进避墙，但覆盖路线混乱 |
| 1M - 2M | 形成系统性覆盖策略（如弓字形路线） |
| 2M - 3M | 优化路线效率，稳定避开物体 |

### 7.2 成功标准

| 指标 | 目标 |
|------|------|
| 覆盖率 | > 80%（触发早停） |
| 物体碰撞 | < 5 次/episode |
| 墙壁碰撞 | < 2 次/episode |

### 7.3 回放观察要点

| 行为 | 好的表现 | 需改进 |
|------|---------|--------|
| 路线规划 | 系统性弓字形或螺旋形 | 随机乱走，重复覆盖 |
| 物体回避 | 提前减速绕开 | 直接碾过物体 |
| 墙边处理 | 平行于墙移动 | 频繁擦墙 |
| 效率 | 在 120 秒内达到 80% | 超时仍未达到 50% |

## 8. 常见问题

### Q1: 覆盖率始终在 20-30% 停滞

**原因：** 机器人只在小区域内打转。
**解决：** 增大 `forward_bonus`（0.3→0.5）或增大 `entropy_loss_scale`。

### Q2: 物体碰撞次数很多

**原因：** OracleDetector 的 FOV 范围（2.0m）内物体不被正确检测。
**排查：** 检查 detector 输出是否正确传入观测。

### Q3: 机器人总是沿墙走

**原因：** 沿墙是一种安全但低效的策略。
**解决：** 增大 `coverage` 奖励权重（2.0→3.0），使覆盖新区域的激励更强。
