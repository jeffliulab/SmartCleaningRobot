## 1. 任务描述

### 1.1 目标

训练 JetBot 机器人在室内场景中尽可能多地覆盖地面面积——本质上就是训练一个扫地机器人的路径规划策略。

### 1.2 与 T1 MazeEscape 的区别

| 维度 | T1 MazeEscape | T2 Coverage |
|------|---------------|-------------|
| 目标 | 到达一个固定出口 | 覆盖整个地面 |
| 场景 | 小迷宫 (8×8) | 大型室内环境 (最大 30×30m) |
| 奖励 | 距离出口越近越好 | 覆盖新区域获得奖励 |
| 观测 | 41 维（紧凑） | 1102 维（含局部覆盖地图） |
| 难点 | 路径规划/避墙 | 全局覆盖策略/不重复 |
| Episode | 120 秒 | 300 秒 |

### 1.3 可用场景

| 场景名 | 尺寸 | 复杂度 | 说明 |
|--------|------|--------|------|
| hospital | 30×30m | 高 | 默认场景，多房间走廊 |
| office | 20×20m | 中 | 开放式办公区 |
| warehouse | 24×24m | 低 | 大型空旷仓库 |
| simple | 8×8m | 极低 | 空房间（调试用） |

## 2. 背景知识

### 2.1 覆盖率追踪（Coverage Tracker）

整个地面被划分为 5cm×5cm 的网格。机器人经过时，其周围 6cm 半径内的格子被标记为"已覆盖"。

```
覆盖率 = 已覆盖格子数 / 总可达格子数
```

**网格分辨率：** 0.05m = 5cm
**机器人覆盖半径：** 0.06m = 6cm

以 hospital 场景 (30×30m) 为例：
- 总格子数 ≈ 600 × 600 = 360,000（但被墙壁和家具占据的不算）
- 可达格子数取决于场景布局

### 2.2 局部覆盖地图

策略网络不仅知道全局覆盖率（一个数字），还能"看到"自己周围的覆盖情况：

```
32×32 的局部视野（以机器人为中心）

□□□□□□□□□□□□
□□□□■■■□□□□□
□□□■■■■■□□□□
□□■■■██■■□□□    ██ = 机器人
□□□■■■■■□□□□    ■ = 已覆盖
□□□□■■■□□□□□    □ = 未覆盖
□□□□□□□□□□□□

每格 5cm × 32格 = 1.6m × 1.6m 的视野
```

这个 32×32 = 1024 维的二值矩阵帮助策略决定"往哪个方向走能覆盖新区域"。

## 3. 环境详解

### 3.1 观测空间（1102 维）

| 组件 | 维度 | 范围 | 说明 |
|------|------|------|------|
| pose | 3 | 连续 | 世界坐标 (x, y, yaw) |
| velocity | 2 | 连续 | 前进线速度 + 角速度 |
| lidar | 72 | [0,1] | 360→72 射线归一化距离 |
| local_coverage | 1024 | {0,1} | 32×32 局部覆盖网格（展平） |
| coverage_ratio | 1 | [0,1] | 全局覆盖率 |

**为什么观测这么大（1102 维）？**
主要是 1024 维的局部覆盖地图。这让策略能看到哪些区域已经扫过、哪些还没扫。

### 3.2 动作空间（2 维）

| 索引 | 含义 | 范围 | 物理量 |
|------|------|------|--------|
| 0 | 线速度 | [-1,1] | ×0.3 → m/s |
| 1 | 角速度 | [-1,1] | ×2.0 → rad/s |

### 3.3 Episode 流程

```
1. [重置] 机器人在场景中随机位置/朝向出生，覆盖网格清零
2. [循环] 每步:
   a. 读取观测 (位姿 + 速度 + LiDAR + 局部覆盖 + 全局覆盖率)
   b. 策略输出动作 (线速度 + 角速度)
   c. 仿真执行 2 步
   d. 更新覆盖网格
   e. 计算奖励（覆盖新区域 + 里程碑奖励 - 碰撞 - 时间）
   f. 终止条件:
      - 覆盖率 ≥ 98% → 完美完成
      - 超时 300 秒 → 截断
3. [结束] 记录数据，重置
```

## 4. 奖励函数详解

| 组件 | 权重 | 触发条件 | 设计意图 |
|------|------|---------|---------|
| coverage | +10.0 | 每步新覆盖的格子数 | 核心奖励：探索新区域 |
| milestone_bonus | +50.0 | 覆盖率达到 50%/75%/90%/95% | 一次性大额奖励，激励持续进步 |
| collision_penalty | -5.0 | LiDAR 最小距离 < 0.20m | 惩罚撞墙 |
| forward_bonus | +0.3 | forward_vel.clamp(min=0) | 鼓励前进 |
| time_penalty | -0.01 | 每步固定 | 鼓励高效清扫 |

### 里程碑系统

| 里程碑 | 奖励 | 说明 |
|--------|------|------|
| 50% 覆盖 | +50 | 首次达到即触发，每 episode 仅一次 |
| 75% 覆盖 | +50 | 同上 |
| 90% 覆盖 | +50 | 同上 |
| 95% 覆盖 | +50 | 同上 |

里程碑奖励解决了"覆盖率从 80% 到 90% 的边角区域很难探索"的问题——给予额外激励。

## 7. 结果分析

### 7.1 预期训练时间线

| 阶段 | 步数 | 行为 |
|------|------|------|
| 0 - 100K | 随机游走，低覆盖率 |
| 100K - 500K | 学会前进避墙，覆盖率 ~30-40% |
| 500K - 800K | 形成初步路线策略 |
| 800K - 1M | 覆盖率 ~60%+，路线更系统化 |

> 要达到更高覆盖率（80%+），可能需要增加训练步数到 3-5M。

### 7.2 成功标准

| 指标 | 基础目标 | 优秀目标 |
|------|---------|---------|
| 覆盖率 | > 60% | > 80% |
| 碰撞次数 | < 10/episode | < 3/episode |
| 达到 50% 的时间 | < 200 秒 | < 100 秒 |

### 7.3 回放观察要点

| 行为 | 好的表现 | 需改进 |
|------|---------|--------|
| 路线规划 | 弓字形/螺旋形系统覆盖 | 随机乱走，大片遗漏 |
| 避障 | 平行于墙壁移动 | 频繁撞墙 |
| 效率 | 不重复已覆盖区域 | 反复走同一条路 |
| 转角处理 | 清扫到角落 | 角落和边缘遗漏 |

### 7.4 典型覆盖策略

训练成功后，机器人通常会学到以下策略之一：

1. **弓字形策略：** 像打印机一样来回扫（最高效）
2. **螺旋策略：** 从外圈向内圈螺旋
3. **分区策略：** 先清扫一个区域，再移到下一个

## 8. 常见问题

### Q1: 1M 步后覆盖率还不到 30%

**原因：** 大场景（hospital 30×30m）可能需要更多训练。
**解决：**
- 增加训练步数到 5M
- 先在 `simple` 场景上训练，验证算法正确后再换大场景

### Q2: 机器人只在角落打转

**原因：** 策略陷入局部最优。
**解决：** 增大 `entropy_loss_scale`（0.01→0.03），增大 `forward_bonus`。

### Q3: 观测维度 1102 导致训练很慢

**说明：** 这是已知的设计权衡——1024 维局部地图提供了丰富的空间信息，但增加了计算量。
**建议：** 如果 GPU 显存紧张，减少 `num_envs`（64→32）。

### Q4: 碰撞太多

**解决：** 增大 `rew_collision_penalty`（-5.0→-10.0），让碰撞惩罚更重。

### Q5: 如何切换场景？

修改 `env_cfg.py` 第 46 行：
```python
scene_name: str = "office"  # 或 "simple", "warehouse", "hospital"
```
